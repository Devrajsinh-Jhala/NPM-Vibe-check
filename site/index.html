The npm 12 problem

npm asks you a question it can’t answer

What npm gives you

Since 12.0, preinstall, install and postinstall are off by default. Every project now maintains an allowScripts list, and npm approve-scripts shows you which packages are waiting on a decision — and the command text. 

$ npm approve-scripts --allow-scripts-pending

  better-sqlite3  install: prebuild-install || node-gyp rebuild
  esbuild         postinstall: node install.js
  sharp           install: node-gyp rebuild

That is the whole answer. Approve or don’t.

What you actually need to know

Does it reach the network? Read environment variables? Write outside its own directory? npx-vibe downloads the tarball, verifies its integrity, reads the script and the files it pulls in, and answers exactly that.

  • approve Local compilation only — every command segment is a build tool.
  • review Fetches a binary or spawns a shell. Here is the line; you decide.
  • deny Reads credentials and sends them. Not a judgement call.

--write records only the unambiguous decisions. Anything needing review is deliberately left for a person.

Works on npm 10 and 11 as well as 12 — it reads package-lock.json directly, so you can settle the list before you upgrade.

How it works

Four steps, no execution

  1. 01

    Resolve and verify

    Resolve the exact version npm would install, download the registry tarball, and check it against the registry’s own integrity hash before anything is read.

  2. 02

    Read the code

    Parse the archive in memory. Follow install hooks, bin entry points, and the relative imports reachable from them. Nothing is unpacked to disk and nothing is executed.

  3. 03

    Decide with evidence

    Every finding carries a file, a line number, and the matched source. Known advisories come from OSV. Registry age and popularity are shown as context and never move the score.

  4. 04

    Remember the answer

    Review memory is keyed by the verified tarball hash, not by name and version. A republished version with different bytes reads as changed, not as already seen.

Integrations

Built for people, native for agents

Command line

Scanning is the default and never executes anything. npx-vibe run is the only command that does.

npx npx-vibe esbuild
npx npx-vibe run esbuild -- --version

MCP server

Four schema-backed, read-only tools over stdio. Credentials never travel as tool arguments.

npx npx-vibe --mcp

scan_package · scan_project · approve_scripts · list_providers

Any other CI

Exit 0 proceed, 2 review, 3 block. Nothing GitHub-specific is required.

npx npx-vibe --project . --json
npx npx-vibe approve-scripts

Coding agents

Versioned, fail-closed JSON. An agent continues only on action: "continue".

npx --yes npx-vibe@latest --agent <package>

GitHub Action

One step. Annotations and a job summary, with a fail-on policy you choose.

- uses: Devrajsinh-Jhala/NPM-Vibe-check@v2
  with:
    command: approve-scripts
    fail-on: caution

On the GitHub Marketplace

Evidence, not scores

You can check the work

A number you cannot audit is a number you eventually ignore. Every deterministic finding names the file, the line, and the text that matched, so you can disagree with the tool and be right.

When optional AI review is enabled, model claims are checked against the source that was actually sent. An unverified claim cannot move a verdict — and no model runs unless you ask for one.

Project preflight

The tree, not just the next command

Compromises reach you through a transitive dependency, so a project scan walks the whole installed tree from package-lock.json by default. Download counts and advisories are batched, so a large tree is a couple of requests rather than hundreds. 

npx npx-vibe --project .
npx npx-vibe --project . --direct-only
npx npx-vibe --project . --include-dev --ci

Workspace links, git dependencies and URL specifiers stay outside the registry-only trust boundary and are reported as skipped rather than resolved through another path. Without a lockfile the scan narrows to direct dependencies and says so, instead of failing. 

Scanned: 68/68 dependencies (direct and transitive)
Proceed: 68  Caution: 0  Block: 0

One deliberate pause before the next package runs.
